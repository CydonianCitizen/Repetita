# v0.9.0 Study Controls, Revision & Exam Mastery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement all features defined for Repetita v0.9.0: fine-grained card management (Set Due Date, Reset Progress, Create Copy), Leech Detection, 4-color Card Flags, FSRS Fuzz Factor, Pause Scheduler (Vacation Mode), Rolling Auto-Backup, and the Exam Scheduler (study planning by exam date).

**Architecture:** 
- Unified Drift Schema v7 migration adding `flag` to `Cards`, and `examDate`/`targetRetention` to `Decks`.
- Pure Dart domain modules for deterministic logic (`ExamStudyPlanner`, `FSRS Fuzz calculation`).
- DAOs and Riverpod Controllers handling atomic state transitions, batch updates, and reactive notifications.
- Responsive Material 3 UI additions in `StudyScreen`, `DeckDetailScreen`, `BackupScreen`, and `SettingsScreen`.

**Tech Stack:** Flutter, Dart, Drift (SQLite), Riverpod, Material 3.

**Spec:** [`ROADMAP.md`](file:///c:/Users/thoma/Documents/Projects/repetita/ROADMAP.md) §7 (Dati & Utilità di Revisione), §8 (Scheduling Avanzato), §12 (Esami).

## Global Constraints

- Offline-first: zero cloud dependencies, all computations and backups run on local filesystem/SQLite.
- Schema compatibility: robust migration from Drift schema v6 to v7 in `app_database.dart` with preservation of existing user data.
- UI Ergonomics: consistent Material 3 design tokens, adaptive for both Mobile and Desktop (Windows/macOS).
- Test integrity: all pure mathematical/domain logic must have 100% unit test coverage; UI changes covered by integration/widget tests.

## Review Focus

1. **Card Reset Progress**: Resetting card progress must reset `state`, `reps`, `lapses`, `stability`, `difficulty`, and `easinessFactor`, but must NOT delete the existing `ReviewLogs` (historical retention analytics must be preserved).
2. **Vacation Mode Date Shift**: Shifting card due dates after a vacation must apply strictly to non-suspended cards in `learning` or `review` states (`state IN (1, 2)`); new cards in queue must retain their relative ordering and not be shifted.
3. **Leech Detection Threshold**: Leech actions ('tag' or 'tag_and_suspend') must trigger deterministically only when `lapses` reaches or exceeds the threshold upon an `Again` rating.
4. **Exam Scheduler Backlog Overflow**: When total required daily cards exceed student daily study time capacity, the planner must warn of an unsustainable backlog without crashing or producing negative numbers.
5. **Rolling Backup FIFO**: Rolling backup must clean up only automatic backup snapshots past retention limit (default 8) without touching manual backup files.
